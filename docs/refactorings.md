# Refactoring catalog: what shapr can prove

Which refactorings and tidyings a two-tree, local-scope detector can label *with proof*, and which it must leave as `logic`. The rule throughout: a pattern earns a structural label only when behavior equivalence follows from the two syntax trees plus local scope facts, or from a stated precondition that shapr can check. Sources are linked at the end; every one was opened. "Safe" below quotes RuboCop's own term; shapr still says "structure".

## 1. What to add next

In order:

1. **`style` as "same tree modulo lexical tokens."** One mechanism covers most autocorrect churn (RuboCop's `StringLiterals`, `HashSyntax`, `BlockDelimiters`, `RedundantParentheses`, `AndOr`, `IfUnlessModifier`; rustfmt's `use_field_init_shorthand`, `remove_nested_parens`). Prism has already resolved precedence and block binding, so equal trees are the proof. A textual rewrite needs the precondition; shapr, comparing trees, doesn't.
2. **Rust `use`-tree normalization** (order, merge and split, nesting) as `style`. rustfmt's `reorder_imports` is on by default, so every formatter run produces these hunks. The proof is equality of the flattened set of `(path, alias, visibility, attributes)` leaves.
3. **Rust lint and tool attributes** (`#[allow]`, `#[expect]`, `#[warn]`, `#[deny]`, `#[rustfmt::skip]`, `#[clippy::…]`, `#[must_use]`, `#[deprecated]`, `#[doc(hidden)]`). They are compile-time only, so a closed allowlist of names proves it. Today they count as `logic`.
4. **Guard clause family** (planned): nested `if` to early `return`/`next`, redundant `else` after a jump, `unless/else` to swapped `if/else`. RuboCop marks `Style/GuardClause` safe. Two preconditions are missing from the plan: `def` or lambda only, and no `rescue … else`.
5. **Redundant `return`** (`Style/RedundantReturn`, Clippy `needless_return`). It's frequent and cheap. Rust needs a drop-order precondition: either the expression creates no temporaries or the edition is 2024.
6. **Extract and inline variable** (planned). It's the most-used tool refactoring after Rename and Move (5.6% of Eclipse tool uses), and detectors get the inline direction wrong most often (ActRef precision 0.37). So prove only the single-use, adjacent, no-reordering case.
7. **Consolidate conditional**: nested `if` without `else` to `&&` (Clippy `collapsible_if`, RuboCop `SoleNestedConditional`), and consecutive `if c; return v; end` with identical bodies to `||`. `&&` and `||` can't be redefined, so the trees prove it.
8. **Rust bool-only simplifications**: `if c { true } else { false }` to `c`, and `match x { P => e, _ => () }` to `if let P = x { e }`. An `if` condition is `bool` by typing, so no type inference is needed. The Ruby look-alike is not equivalent.
9. **Reuse an existing function** (Fowler's *Replace Inline Code with Function Call*): a chunk is replaced by a call to a method that exists unchanged on both sides. It's the extract proof without the "new method" half.
10. **Explaining constant** (planned), narrowed: Rust `const` holding a suffixed literal or a declared type, and Ruby holding an immutable literal only. Both languages break the general case (type inference in Rust; load-time evaluation and shared identity in Ruby).
11. **Rust inlined format args** (`format!("{}", x)` to `format!("{x}")`, Clippy `uninlined_format_args`). Common in Rust codebases. Provable for std formatting macros when the argument is a bare identifier, with the edition checked for `panic!`.
12. **Narrowed `delete_dead`** (planned): code after an unconditional keyword jump, and a removed unused local whose right-hand side is a literal or a local read. Anything wider needs whole-program facts that shapr doesn't have (see §5).

## 3. `style` normalization

### Provably equivalent pairs

Compare the trees after normalizing only what the "Normalize" column says. Everything else stays exact.

| Lang | Pair | Normalize | Condition |
|---|---|---|---|
| R | `'abc'` ↔ `"abc"` ↔ `%q(abc)` ↔ `%Q(abc)` ↔ `?a` (one char) ↔ a non-interpolating heredoc | `StringNode`: compare `unescaped` bytes plus the forced-encoding and frozen/mutable flags | No interpolation (an `InterpolatedStringNode` stays exact). The encoding flags matter: `"é"` forces UTF-8. |
| R | `:abc` ↔ `:"abc"` | `SymbolNode.unescaped` | Not a dynamic symbol. |
| R | `{:a => 1}` ↔ `{a: 1}`, and `{:"a b" => 1}` ↔ `{"a b": 1}` | `AssocNode` key compared as a symbol value; ignore `=>`/`:` | The key is a `SymbolNode` on both sides (see the look-alikes for `"a": 1`). |
| R | `{x: x}` ↔ `{x:}` | `ImplicitNode` ↔ the explicit value | The explicit value is the same local read or variable call `x` that prism resolves for the shorthand. |
| R | `foo(a: 1)` ↔ `foo(:a => 1)` ↔ `foo(**{a: 1})` | `KeywordHashNode` contents | Stays a keyword hash (no braces added; see below). |
| R | `foo(x) { … }` ↔ `foo(x) do … end` | Ignore `BlockNode` delimiters | **The block is attached to the same `CallNode` in both trees.** Parentheses alone don't decide it: `puts foo(a) { }` attaches to `foo`, while `puts foo(a) do end` attaches to `puts` (checked with prism). |
| R | `foo(a)` ↔ `foo a`, `foo()` ↔ `foo`, `def f()` ↔ `def f`, `def f(a)` ↔ `def f a` | Ignore call and def paren locations | Same `CallNode` arguments, and both are calls: prism makes `foo` a local read when a local `foo` is in scope, and then the trees differ. |
| R | `(expr)` ↔ `expr` | A single-statement `ParenthesesNode` is transparent | Exactly one statement inside: `(a; b)` is a sequence. |
| R | `a and b` ↔ `a && b`, `a or b` ↔ `a \|\| b` | `AndNode`/`OrNode` operator spelling | Trees equal after the parse. RuboCop's `AndOr` autocorrect is unsafe only because rewriting the text reparses with different precedence. Equal trees already settle that. |
| R | `not x` ↔ `!x` | Both are `CallNode` `!` | None (checked: both parse to `:!`). |
| R | `x if c` ↔ `if c; x; end`, `c ? a : b` ↔ `if c; a; else; b; end`, the `then`/`;`/newline forms | `IfNode`/`UnlessNode` keyword locations | Not `while`/`until`: `begin … end while c` has `begin_modifier?` (do-while) and must match. |
| R | `unless c; a; else; b; end` ↔ `if c; b; else; a; end` | Swap branches | None. |
| R | `f.(x)` ↔ `f.call(x)`, `a::b` ↔ `a.b` (method call) | `CallNode` `call_operator_loc` | Both are `CallNode`s with name `call` (checked) or `b`. `a::B` is a constant. |

| R | `1000` ↔ `1_000` ↔ `0x3e8`, `1.0` ↔ `1.00` | `IntegerNode`/`FloatNode` value | Equal value (checked: `1_000` and `0x3e8` both 1000). Rational and imaginary suffixes must match. |
| R | `[1, 2,]` ↔ `[1, 2]`, trailing comma in a hash or call argument list | Ignore the comma | Not in block parameters, and not `a, = x` (see below). |
| R | `def f = x` ↔ `def f; x; end` | `DefNode` body shape | One-expression body. |
| R | `x = x \|\| y` ↔ `x \|\|= y`, `x = x + 1` ↔ `x += 1` | Write node forms | The target is a local, ivar or global variable. |
| Rs | `S { a: a }` ↔ `S { a }` (expression and pattern) | Field-init shorthand | Same field name. |
| Rs | `((e))` ↔ `(e)` ↔ `e` | `parenthesized_expression` is transparent | A single expression. A one-element tuple `(e,)` is code. |
| Rs | `use a::{b, c};` ↔ `use a::b; use a::c;` and any order | Flattened leaf multiset | Per leaf: same visibility and `cfg`. `{self}` is not the bare path. |
| Rs | `#[derive(A, B)]` ↔ `#[derive(B, A)]` ↔ `#[derive(A)] #[derive(B)]` | Derive multiset | Proven for std derives only. |
| Rs | `const X: &'static str` ↔ `const X: &str` | Elided `'static` in `const`/`static` types | Only in `const` and `static` item types. |
| Rs | `fn f() -> () {}` ↔ `fn f() {}`; tail `()` in a unit fn ↔ none | Unit return | None. |
| Rs | `1_000` ↔ `1000` ↔ `0x3e8`, `1e3` ↔ `1000.0` | Literal exact value | Same suffix, or both unsuffixed. Equal exact rationals round identically. |
| Rs | `return x;` at the tail ↔ `x` | Return elision | Edition 2024, or `x` creates no temporaries (row 8). |
| Rs | `if c { true } else { false }` ↔ `c` | `needless_bool` | None (`c: bool`). |
| Rs | `format!("{}", x)` ↔ `format!("{x}")` | Format-string arguments | Row 20. |

### Look-alikes that are NOT equivalent

| Lang | Pair | Why not | Source |
|---|---|---|---|
| R | `{"a": 1}` ↔ `{"a" => 1}` | The first key is the symbol `:a` (checked: `SymbolNode`); the second is a string. | Ruby syntax |
| R | `foo(a: 1)` ↔ `foo({a: 1})` | Keyword arguments vs a positional hash (Ruby 3). | Ruby 3 keyword separation |
| R | `puts foo(a) { }` ↔ `puts foo(a) do end` | `do…end` binds to the outer parenless call. | Prism (checked) |
| R | `\|a,\|` ↔ `\|a\|` | The trailing comma destructures: `[[1,2]].map { \|a,\| a }` is `[1]`, while `\|a\|` gives `[[1,2]]` (checked). | RuboCop `Style/TrailingCommaInBlockArgs` (unsafe) |
| R | `begin x end while c` ↔ `while c; x; end` | Do-while runs the body first. | Prism `begin_modifier?` |
| R | `x.map { \|y\| y.foo }` ↔ `x.map(&:foo)` | `Symbol#to_proc` is a lambda: arity errors differ. | `Style/SymbolProc` (unsafe) |
| R | `x && x.foo` ↔ `x&.foo` | `false&.foo` raises, and intermediate `nil`s get swallowed. | `Style/SafeNavigation` (unsafe autocorrect) |
| R | `!!x` ↔ `!x.nil?` | They differ when `x` is `false`. | `Style/DoubleNegation` (unsafe autocorrect) |
| R | `c ? true : false` ↔ `c` | A truthy value vs a boolean. | `Style/IfWithBooleanLiteralBranches` (unsafe autocorrect) |
| R | `b ? b : c` ↔ `b \|\| c` | `b` is evaluated twice vs once when it's a method call. | `Style/RedundantCondition` (safe in RuboCop, but not equivalent unless `b` is a variable) |
| R | `x == nil` ↔ `x.nil?`; `x != nil` ↔ `!x.nil?` | `==`, `!=` and `!` are user-definable methods. | `Style/NilComparison`, `Style/NonNilCheck` (safe in RuboCop: no false positives by design, not a proof) |
| R | `a == x \|\| a == y` ↔ `[x, y].include?(a)` | `include?` calls `x == a` (receiver swapped), and `a` is evaluated once. | `Style/MultipleComparison` (safe in RuboCop) |
| R | `if !c` ↔ `unless c` | `!` is a method; `unless` doesn't call it. | Ruby semantics |
| R | `x == 0` ↔ `x.zero?`; `x.length == 0` ↔ `x.empty?` | The receiver's type is unknown. | `Style/NumericPredicate`, `Style/ZeroLengthPredicate` (unsafe) |
| R | `0 == x` ↔ `x == 0` | `==` is not symmetric across classes. | `Style/YodaCondition` (unsafe) |
| R | `if x == a … elsif x == b` ↔ `case x when a … when b` | `case` uses `===`. | `Style/CaseLikeIf` (unsafe) |
| R | `"a" + b` ↔ `"a#{b}"` | `+` requires a String (`TypeError`), while interpolation calls `to_s`. | `Style/StringConcatenation` (unsafe) |
| R | `"#{x}"` ↔ `x.to_s` | A new string vs possibly the same (frozen) object. | `Style/RedundantInterpolation` (unsafe autocorrect) |
| R | adding `# frozen_string_literal: true`; `FOO = []` ↔ `FOO = [].freeze` | Mutation now raises `FrozenError`. | `Style/FrozenStringLiteralComment`, `Style/MutableConstant` (unsafe autocorrect) |
| R | `String.new` ↔ `''` | `String.new` is ASCII-8BIT, `''` is the source encoding (checked: BINARY vs UTF-8). | Ruby core |
| R | `module A; class B` ↔ `class A::B` | Lexical constant lookup (`Module.nesting`) differs, and the compact form needs `A` to already exist. | `Style/ClassAndModuleChildren` (unsafe autocorrect) |
| R | group `private` ↔ `private def x` | Visibility of dynamically defined methods differs. | `Style/AccessModifierDeclarations` (unsafe autocorrect) |
| R | `for x in xs` ↔ `xs.each { \|x\| }` | `for` leaks `x` to the enclosing scope. | `Style/For` (unsafe autocorrect) |
| R | `t = a; a = b; b = t` ↔ `a, b = b, a` | `t` may be read later. | `Style/SwapValues` (unsafe autocorrect) |
| R | reordering `require`s; removing a duplicate `require` | Load order is behavior. | `Style/RequireOrder`, `Lint/DuplicateRequire` (unsafe autocorrect) |
| R | hoisting identical leading branch statements above an `if` | It moves code before the condition's side effects. | `Style/IdenticalConditionalBranches` (unsafe autocorrect) |
| R | removing an empty `initialize`, or `def x; super; end` | Arity, a raising superclass `initialize`, visibility. | `Style/RedundantInitialize`, `Lint/UselessMethodDefinition` (unsafe) |
| R | `def f(a = 1, b)` ↔ reordered optionals | It changes the signature. | `Style/OptionalArguments` (unsafe) |
| R | `keys.each` ↔ `each_key`; `!x.any?` ↔ `x.none?` | The receiver's type is unknown, and inverse methods may not be true inverses. | `Style/HashEachMethods`, `Style/InverseMethods` (unsafe) |
| R | hash literal key reorder; keyword-argument reorder | Insertion order is observable (`**opts`, iteration), and value evaluation order changes. | Ruby `Hash` ordering |
| R | `super` ↔ `super(a, b)` | Zsuper passes the parameters' *current* values and every keyword argument. | Ruby semantics |
| R | `obj.a \|\|= v` ↔ `obj.a = obj.a \|\| v` | The setter is skipped when `obj.a` is truthy. | Ruby semantics |
| Rs | `#[derive(Foo, Bar)]` reordered, third-party | Proc macros run arbitrary code in order. | Rust reference (derive macros are proc macros) |
| Rs | `use a::{self}` ↔ `use a` | `self` imports only the module namespace. | Rust `use` semantics |
| Rs | struct *declaration* field reorder; enum variant reorder | Derived `Ord`/`PartialOrd`/`Hash`/`Debug` output, `repr(C)` layout, field drop order, implicit discriminants. | Rust reference |
| Rs | `1u8` ↔ `1`; `let x: u64 = 5` ↔ `let x = 5` | Literal type inference changes. | Rust inference |
| Rs | `!(a < b)` ↔ `a >= b` | `PartialOrd` with NaN. | Clippy `neg_cmp_op_on_partial_ord` |
| Rs | `x == true` ↔ `x` | `PartialEq<bool>` can be implemented on any type. | Type-dependent |
| Rs | `&x` ↔ `x` in an argument | `&T` and `T` impls may differ. | Clippy `needless_borrow` known problems |
| Rs | `for x in v.iter()` ↔ `for x in &v`; `x.len() == 0` ↔ `x.is_empty()` | Library convention, not language rule. | Type-dependent |
| Rs | `x.clone()` removed | Needs flow and type analysis. The lint sits in `nursery`. | Clippy `redundant_clone` |
| Rs | `\|x\| f(x)` ↔ `f` | Type adjustments and coercions. Clippy skips adjusted calls; shapr can't see them. | Clippy `redundant_closure` |
| Rs | `let x = e; x` ↔ `e` (tail) | Lock and guard temporaries change drop timing. | Clippy `let_and_return` known problems |
| Rs | `match` arm reorder | Overlapping patterns and guards. | Rust semantics |

## 4. Skip

| Pattern (source) | Why skip |
|---|---|
| Pull Up / Push Down Method or Field, Extract Superclass/Subclass/Interface, Collapse Hierarchy, Inline/Extract Class (Fowler, RefactoringMiner) | Equivalence depends on dispatch across the whole hierarchy and on callers outside the change. In Ruby, method lookup order (`include`/`prepend`) and `super` chains change. Not provable locally. |
| Move Field, Encapsulate Variable/Collection/Record, Remove Setting Method, Hide Delegate, Remove Middle Man | Every accessor caller, including unseen ones (`send`, templates, serializers), must change consistently. Encapsulation also adds an overridable dispatch point. |
| Replace Temp with Query, Replace Derived Variable with Query | The evaluation count goes from once to every read, and the query can be overridden. |
| Split Loop, Replace Loop with Pipeline (and the reverse), Replace Control Flag with Break | Iteration order, evaluation count, and laziness or type-dependent pipeline methods. Needs flow analysis. |
| Substitute Algorithm, Parameterize Function, Combine Functions into Class/Transform, Replace Function with Command (and the reverse), Split Phase, Separate Query from Modifier, Return Modified Value | Behavior change or an unbounded rewrite. Nothing to align. |
| Replace Conditional with Polymorphism, Introduce Special Case, Replace Type Code with Subclasses, Replace Subclass with Delegate, Replace Superclass with Delegate | Moves logic into dispatch. Not locally provable. |
| Replace Error Code with Exception, Replace Exception with Precheck, Introduce Assertion | Behavior change by definition. |
| Introduce Parameter Object, Preserve Whole Object, Remove Flag Argument, Replace Parameter with Query (and the reverse) | Signature and every call site change, and the object's identity and laziness differ. At most a hedged `change_signature`. |
| Replace Constructor with Factory Function | Adds dispatch, and `new` can be overridden. |
| Decompose Conditional | It is Extract Method on an expression. Generalize `extract` to an expression chunk rather than a separate kind. |
| Move Statements into Function / to Callers | Extract or inline across every caller. Wait for the multi-part model, then reuse the extract proof with an unseen-caller Laplace term. |
| Beck: New Interface, Old Implementation | A new method delegating to an old one is an *addition*. In Ruby a new method can override a parent's, intercept `method_missing`, or change `respond_to?`. It's not structure, though shapr could report "added, unused in change" as a signal. |
| Beck: Explicit Parameters, Normalize Symmetries | Signature change, or a free-form rewrite. A normalized symmetry that happens to be a §3 pair is already `style`. |
| Beck: Chunk Statements, Explaining Comments, Delete Redundant Comments | Already `format_only` / `comment_only`. |
| Beck: Extract Helper, One Pile | Already `extract` / `inline`. |
| Beck: Reading Order, Cohesion Order (methods and items) | Already `move`. Statement-level reordering is row 25. |
| RefactoringMiner migrations (Replace Anonymous with Lambda, Try With Resources, Merge Catch, Diamond) | Java-specific. |
| RefactoringMiner type changes (Change Variable/Parameter/Return/Attribute Type), modifier changes | Behavior or interface. Rust type annotations matching inference can't be proven without inference. |
| Rename file / move file | Not a hunk. In Rust it changes the module path; in Ruby, autoload (Zeitwerk) expects the constant at its path. Leave as is. |
| `x.map { \|y\| y.f }` ↔ `&:f`, `lambda {}` ↔ `->(){}`, `proc {}` ↔ `Proc.new {}`, `Array.new` ↔ `[]` | Lambda arity semantics (`SymbolProc` unsafe), or a method call (`Kernel#lambda`, `Array.new`) that can be redefined vs syntax. Low value next to the risk. |
| `def m(*a, **k, &b)` ↔ `def m(...)` (RuboCop `ArgumentsForwarding`) | `Method#parameters` changes, and the body can no longer name the arguments. |
| Clippy type-dependent lints: `needless_borrow`, `redundant_clone`, `redundant_closure`, `bool_comparison`, `len_zero`, `explicit_iter_loop`, `question_mark` on `Result` (`?` applies `From::from`), `manual_map`, `match_like_matches_macro` (MaybeIncorrect), `manual_let_else` (HasPlaceholders) | Equivalence needs types or trait resolution that tree-sitter doesn't give. |

## 5. Notes on the planned items

| Planned item | Problem as described | Make it sound by |
|---|---|---|
| Multi-part model | A part proven against the before tree alone can be invalidated by the residual logic (for example, a rename's "nothing else uses the new name" broken by an added line). | Define the residual as `diff(before, undo(parts, after))`, and re-run each part's checks against the after tree *including* the residual. A part whose checks fail folds back into the residual. |
| Non-code categories (docs, config) | Config is behavior (`database.yml`, `Cargo.toml` features, CI YAML, `.gitattributes`). Rust docs can be code: fenced Rust in `///` and `//!` runs as doctests, and `#![doc = include_str!("../README.md")]` turns a README into doctests. | Label config `logic` (or a `config` category counted as behavior). For docs, check whether a Rust crate `include_str!`s the file, and treat changed fenced Rust code in doc comments as test code, not `comment_only`. |
| `style`: braces vs `do/end` "with parens" | Parentheses on the block's call aren't sufficient: `puts foo(a) { }` ≢ `puts foo(a) do end` (the outer parenless call steals `do`). They aren't necessary either (`foo { }` ↔ `foo do end`). | The condition is that the block attaches to the same `CallNode` in both prism trees. |
| `style`: quote style | "No escapes or interpolation" is narrower than needed, and `"é"` vs `'é'` differs in encoding flags. | Compare `unescaped` bytes plus `StringNode` flags (forced UTF-8/binary, frozen/mutable). |
| `style`: hash syntax | `{"a": 1}` looks like a string key but is a symbol. | Compare the key's node type and value, never its spelling. |
| `style`: Rust `use` order | Must exclude moving a `macro_rules!` or `#[macro_use] mod` across the run. `{self}` ≠ the bare path. | Leaf-multiset equality per module, per `cfg`/visibility. |
| `style`: derive order | Sound for std derives only. | Hedge (confidence < 1) when any derive isn't std. |
| `delete_dead` | Unsound beyond narrow cases. A private Ruby method can be reached through `send`, `method`, callbacks named by symbol, or templates. A private Rust item is visible to child modules in other files and to macros, and `#[no_mangle]`/`#[test]`/trait impls are never dead by name. shapr sees only the diff. | Ship rows 22 and 23 (keyword-unreachable code, a pure unused local) as `delete_dead`. Everything else is `logic`, or a separate *signal* ("no reference in change"), never structure. |
| Extract/inline variable | The plan doesn't mention evaluation order or count, shared identity, closure capture, or Rust drop timing. ActRef's 0.37 precision on Inline Variable shows how easy this is to get wrong. | Rows 11 and 12: single occurrence, adjacent or pure-in-between, not inside a loop, block or short-circuit operand, untyped `let`, plus the `drop` risk check. |
| Extract/inline constant | Ruby evaluates a constant once at load, so a mutable literal becomes shared. Rust `const` type annotations change literal inference. A `static` is not a `const`. | Row 19: immutable literals in Ruby; suffix-matched or single-type literals in a Rust `const`. |
| Guard clause | Missing preconditions: `return` in a proc or block is non-local (use `next`), a `rescue … else` clause is skipped by an early `return`, and an `if !c` form depends on `!` not being redefined. | Row 7. |
| Revert detection | Detection by exact inverse of an earlier commit's diff is sound, but a revert restores old *behavior*: it is a behavior change, not structure. | Report it as a signal (`revert_of: <sha>`) on top of `logic`, and never count it toward the `structure` verdict. |
| Visibility signal | Ruby traps: bare `private` doesn't affect `def self.x` (that needs `private_class_method`), constants (`private_constant`), or methods from `define_method` in every case. `module_function` makes a copy. `protected` is a third state. `private attr_reader :x` is private. | Model visibility per def kind. Mark constants and singleton methods as unaffected by a bare `private`. |
