# Decision log

Every decision, reversal and rework gets a row, so the design keeps its reasons. Newest first.

**Never edit an old row.** Add a new one, mark the old one Superseded, and say what changed and why.

| # | Decision | Why | Status |
|---|---|---|---|
| 33 | The roles-and-context signals (repo relationship, author relationship, experience, file risk) belong in a separate code-context CLI, not shapr | shapr answers what kind of change; that tool answers who and where | Active |
| 32 | Norms live in shapr, not a separate tool: each changed hunk gets a `style` field judged against its surrounding code, and `shapr norms <file>` reports a file's norms; the planned syntax-equivalence part kind is named `restyle` | Same engine, one tool; split out only if standalone use grows | Active |
| 31 | Build new kinds in measured order: test-only split in review numbers, then lexical style, then namespace-crossing moves/renames; guard clause, extract variable, delete_dead, consolidate conditional, redundant return wait for evidence | Corpus (4,778 commits, 5 repos): 0.5% of Ruby/Rust code lines are structural; of 200 sampled logic hunks 52.5% real behavior, 35% test-only, 3.5% style, every other catalog kind 0 to 1.5%. Roadmap ceiling about 11% of logic hunks | Active |
| 30 | Drop verdict exit codes: exit 0 on success, 2 error, 64 usage; the verdict lives in the output. GitHub input stays but is marked experimental until 1.0 | Exit 1 for the commonest outcome broke the `\|\| fail` idiom and is policy in the mechanism; can be re-added opt-in later. GitHub code is large for a narrow tool | Active |
| 29 | Groundwork before new kinds (architecture review): one shared per-file alignment and a deeper Tree; an exhaustive hazard table; proof status with explicit assumptions that aggregates respect; schema pass (file category, unknown bucket, meta record, experimental claims judgement); fixtures as data; a thin grokr slice consuming the JSON | Four private aligners and duplicated Tree helpers would multiply with each new kind; confidence was computed but ignored by the verdict; the schema had no consumer | Active |
| 28 | Non-code files get categories: docs (md, txt, rdoc) and whitespace-only text edits don't count as behavior; config (yml, toml, json, env) stays behavior but is labeled config | All three testers hit it: a README edit flipped any PR to behavior. Config can change runtime behavior, so it stays visible as risk | Active |
| 27 | New shapes: style (functionally equivalent syntax variants), delete_dead, extract/inline variable and constant, guard clause, revert (from git history and PR description), and a public/private visibility signal. A research pass enumerates further deterministically provable refactorings (Fowler, Tidy First?, RuboCop safe/unsafe autocorrects, Clippy) | Real PRs are full of mechanical tidyings that read as logic today; revert is the strongest retrospective risk signal | Active |
| 26 | Multi-part hunks: a hunk is a list of proven structural parts plus a residual logic part with exact lines; kind becomes a rollup; move_with_changes goes away (a move part may carry context) | One label per hunk loses the structural part of rename+edit, extract+edit, move+edit, and can't point at the lines that changed behavior | Active |
| 25 | Public repo at github.com/dpep/shapr with house conventions (squash-only, auto-merge, Dependabot); branch protection skipped during prototyping | Fast iteration now; protection once the surface settles | Active |
| 24 | A relocation into new context (owner, Rust module, visibility, load order, file directives) is move_with_changes with detail.context, not logic; review_lines counts changed lines plus the moved unit's first line | Moving code is mostly refactoring and lower risk than a feature, but not pure structure. A 162-line relocation in rq now reviews 8 lines. Caveat: load_order can hide a real fix (define-before-use) | Active |
| 23 | Rust frontend via tree-sitter. Cross-file moves in Rust are logic (each file is a module, so the owner changes). Extracts that bind locals or take arguments mid-block are logic (risk drop: locals drop at block end). Doc comments are comments; attributes are code; identifiers inside macros are opaque | Language semantics, not just syntax, decide what is structure. The core gained neutral roles and language-wide semantics flags so JS/TS/Python plug in the same way | Active |
| 22 | Lockfiles and generated files (name list, minified assets, linguist-generated) stay logic and drive the verdict, but are left out of review_lines and size sums | A dependency bump is behavior, but its lines aren't read: on 20 faraday commits package-lock.json alone was 1040 of 1234 review lines | Active |
| 21 | review_lines: format, comment, rename and exact move count 0; extract and inline count their code lines; move_with_changes counts only the lines changed inside the moved body | Structure is not free: extract and inline lead bug-linked refactorings, so a reviewer still reads them | Active |
| 20 | Risk model baseline is logistic regression on lines added; Kamei's 14 git-only features ship only if they beat it. Labels: reverts and hotfixes first, SZZ second with shapr's structural hunks excluded from blame. Retrain on a rolling window; record model version with every verdict | Research: lines added alone matches deep JIT models (AUC 0.72 vs 0.71); about half of SZZ bug-fix labels are wrong; JIT models drift after about a year | Active |
| 19 | Schema carries size and evidence: per hunk code/comment lines added and deleted, review_lines, parsed, evidence (method ast\|line, similarity, rename consistency); per file lines_before; summary NF, ND, NS, entropy, structure_share. Confidence is computed from evidence; a parse error falls back to a line diff with capped confidence | Cheap now, a breaking change later; feeds the risk model directly and makes confidence explainable | Active |
| 18 | Add the inline kind. Signature changes are rename only when just names change, else logic. Reordering defs = move; reordering DSL calls = logic. format_only = AST equality with locations stripped. Structure never means safe | Research: extract (54%) and inline (25%) lead bug-linked refactorings; parameter changes aren't behavior-preserving; Ruby punctuation (do/end vs braces) can change binding | Active |
| 17 | Language frontends behind one seam: each parses to a shared normalized tree plus a few language hooks; classification is language-neutral. Ruby via ruby-prism first; Rust via tree-sitter next (dogfood on shapr itself); JS, TS, Python via tree-sitter later. No tree-sitter dependency until the Rust frontend is built | Prism is Ruby's official parser and reports comments and magic comments directly; tree-sitter covers the other languages with one API. Supersedes #6 | Active |
| 16 | Comment-only is its own kind, split from format-only. Comment lines don't count toward behavior-change size; comment bloat and spelling are flagged separately. Magic comments count as code | Comment edits are interesting and low risk, so they shouldn't inflate risk, but bloated comments are still a cost. Magic comments (frozen_string_literal, rubocop:disable, typed:) change behavior or tooling | Active |
| 15 | Two layers: shapr stays a narrow, deterministic CLI; the PR reviewer (working name grokr) is a separate tool that calls shapr, trekr and contour. The TUI stays in shapr and reads labels JSON from any source | Evidence tools stay stable and composable with many consumers (classifier, risk model, size gate); orchestration and the learning loop churn. Follows #5 | Active |
| 14 | CLI is named shapr (the shape of a change) | Names what the narrow tool does; free on crates.io, Homebrew and GitHub. Supersedes #12 | Active |
| 13 | CI history is low priority and out of v1; if used, judge CI at ready-for-review and handle flaky tests separately | Many flaky tests in large repos; red-then-green pushes are weak evidence | Deferred |
| 12 | CLI name deferred | Settle behavior before naming; check crates.io and Homebrew first | Superseded by #14 |
| 11 | Feedback starts in a local TUI, PR comments later | Preview safely until precision earns direct PR interaction | Active |
| 10 | Verdicts write straight to fixtures; Claude Code iterates on the library | Each correction becomes a regression test; keeps the loop tight | Active |
| 9 | TUI is a mode of the classifier, not a separate tool | Feedback loop baked in, not bolted on | Active |
| 8 | Rename detection: consistent old→new identifier pairs, lower confidence if old name appears in strings or symbols | Ruby's dynamic dispatch hides renames from the AST. Refines the first, vaguer rename rule in #7 | Active |
| 7 | Spike detects format-only, rename, move, extract; everything else is logic | Smallest useful set; unknowns default to the safe label | Active |
| 6 | AST diff CLI in Rust, parsing Ruby with tree-sitter | Personal projects are Ruby; Rust suite; already know tree-sitter | Superseded by #17 |
| 5 | Deterministic tools produce evidence; prompts judge only what tools can't settle | Lean on code for signal and repeatability | Active |
